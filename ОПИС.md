# ScoPosAdapter — опис проєкту

`ScoPosAdapter` — окремий процес на ПК каси: **VSS (екран) ↔ цей exe ↔ BAF HTTP**. Фіскал і Adyen він сам не викликає: картка йде через HTTP у 1С, друк eKasa — з 1С на FMSK `:15001`.

```
VSS GUI  --TCP 17002–17005-->  ScoPosAdapter.exe  --HTTP /sco/v1/lanes/{LaneId}/-->  1С (HTTPServices/SCO)
                                      |
                                      +-- HTTP :15002  health / simulate (лише localhost, опційно)
```

Перемикач режиму: `UseErpMock` у `App.config`.

- `true` — чек у пам’яті адаптера (без мережі до 1С).
- `false` — робочі методи чека йдуть у вже реалізовані ендпоінти 1С.

## Карта файлів

### Запуск процесу

| Файл | Що всередині |
|---|---|
| `Program.cs` | Точка входу. Без аргументів — консоль (так VSS запускає exe). `--service` — Windows-служба. Після зупинки `Environment.Exit(0)`, бо потоки бібліотеки DN інакше тримають процес. |
| `AdapterWindowsService.cs` | Обгортка служби `ScoPosAdapter`: `OnStart` / `OnStop` лише викликають `AdapterHost`. |
| `AdapterHost.cs` | Збирає все разом: створює mock або HTTP-клієнт 1С, піднімає debug HTTP, крутить конектор VSS у фоні, перепідключення кожні `VssReconnectSeconds`, коректне закриття сокетів. |
| `AdapterLog.cs` | Лог у консоль і `logs\sco-pos-YYYY-MM-DD.log` поруч із exe. Помилка запису логу POS не валить. |

### Зв’язок з VSS (`Vss\`)

| Файл | Що всередині |
|---|---|
| `Vss\VssConnector.cs` | Клієнт до VSS поверх DN `IfcIScanConnector`. Адаптер **підключається** до портів, які слухає VSS. `PostOpenConnections` = «всі канали відкриті». `Close()` через reflection гасить сокети бібліотеки (у неї немає публічного Stop). |
| `Vss\VssPosAdapter.cs` | **Робочий цикл чека.** Спадкоємець `IfcAllInboundGroupsBaseImpl`: VSS викликає ці методи. При моку веде кошик у пам’яті; при живій 1С прокидає виклик у `IErpClient` і віддає `posStatus` з BAF. |
| `Vss\VssPosAdapter.Unsupported.cs` | Решта ~30 методів Interface 4.0. Не кидають виняток (інакше канал main помре). Або `IFC_ERROR_OTHER` «не підтримується», або `IFC_OK` без дії (журнал, cash management, вік). |

Робочі методи в `VssPosAdapter.cs`:

- каса: `GetStatus`, `CheckError`, `GetGlobalProperties`, `SignOn`, `SignOff`
- чек: `StartTransaction`, `GetItemDetails`, `AddItem`, `VoidEntry`, `VoidTransaction`
- оплата карткою: `PreparePayment`, `UnpreparePayment`, `PayWithCard`, `PerformPayment`, `AddTender` (готівку на живій 1С відхиляє)
- інше: `ProcessCustomerCard` (лояльність), `Special`, `Cancel` (скасовує HTTP, що зараз летить у 1С), `TransactionFinished`

### Зв’язок з 1С (`Erp\`)

| Файл | Що всередині |
|---|---|
| `Erp\ErpModels.cs` | Контракт: `IErpClient` + `ErpResult` (`result`, `posStatus`, `itemDetails`, `failureReason`…). |
| `Erp\HttpErpClient.cs` | Реальні HTTP-виклики. База: `ErpBaseUrl` + `/sco/v1/lanes/{LaneId}/...`. Auth: `None` / `Os` / `Basic`. Окремий таймаут `ErpPaymentTimeoutSeconds` для `payment/card`. |
| `Erp\ErpMapper.cs` | JSON 1С → об’єкти VSS (`IfcPOSStatus`, чек, ціни в центах, `failureReason.untranslatableText`). `IFC_TRY_ALTERNATIVE` → `IFC_ERROR_TRY_ALTERNATIVE`. У tender `currencyAmount` може бути числом — збирається в `{ amount, currencyCode }`. |
| `Erp\MockErpClient.cs` | Без мережі. Реально вміє лише `ResolveItem` (штрихкод `8584000123456` або `TEST*` → Creme 50 ml, 1299 центів). Решта методів mock кидає `NotSupportedException` і **не викликається**, бо при `UseErpMock=true` чек крутиться в `VssPosAdapter`. |

Відповідність VSS → HTTP (коли mock вимкнено):

| Метод VSS | HTTP |
|---|---|
| `GetStatus` / `CheckError` | `GET .../status` |
| `GetGlobalProperties` | `GET .../global-properties` |
| `SignOn` / `SignOff` | `POST .../sign-on`, `sign-off` |
| `GetItemDetails` | `POST .../items/resolve` |
| `StartTransaction` | `POST .../transactions` |
| `AddItem` | `POST .../items` |
| `VoidEntry` | `POST .../items/{entryId}/void` |
| `ProcessCustomerCard` | `POST .../loyalty` |
| `PreparePayment` | `POST .../payment/prepare` |
| `PayWithCard` | `POST .../payment/card` |
| `Special` | `POST .../special` |

`VoidTransaction`, `UnpreparePayment`, `TransactionFinished` у 1С ще заглушки — адаптер **не** б’є в ці URL, лише пише в лог / повертає помилку / читає поточний статус.

### Відладка без GUI VSS

`HttpDebugHost.cs` — `HttpListener` на `http://127.0.0.1:15002/`:

- `GET /health` — процес, mock, чи VSS підключений, остання помилка конектора
- `POST /simulate/getItemDetails` — той самий `GetItemDetails`, що викличе VSS

Це не фіскальний сервіс і не API для 1С. Якщо порт не зайняти, VSS усе одно працює.

| Файл | Що всередині |

| `INSTALL-SCO-PC.txt` | Чекліст переносу на ПК з VSS. |

`bin\` / `obj\` — артефакти збірки, не логіка.

## Куди дивитися, коли щось міняєте

- **Порти / mock / URL 1С / LaneId** → `App.config` (на стенді — `.exe.config`)
- **Як стартує процес і конект до VSS** → `Program.cs`, `AdapterHost.cs`, `VssConnector.cs`
- **Поведінка каси на виклик VSS** → `VssPosAdapter.cs`
- **Новий метод VSS, якого немає в пілоті** → `VssPosAdapter.Unsupported.cs` (зараз заглушка)
- **Новий або змінений HTTP 1С** → `HttpErpClient.cs` + мапінг у `ErpMapper.cs` + метод у `IErpClient`
- **Тест без VSS** → `HttpDebugHost.cs` і `/simulate`
- **Чому «немає POS»** → `logs\sco-pos-*.log` і `/health` (`vssConnected`, `vssLastError`)

Типовий живий шлях: VSS → `VssPosAdapter.PayWithCard` → `HttpErpClient.PayWithCard` → `POST .../payment/card` → JSON → `ErpMapper` → знову `posStatus` у VSS.
